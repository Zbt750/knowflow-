# 程序中断方式

## 概念、定义与适用条件

中断 I/O 下设备就绪或事件发生时向 CPU 请求服务。CPU 可先运行其他程序；接受中断后保存必要现场、识别中断源、执行服务程序搬运数据并恢复现场。中断响应延迟、屏蔽和优先级影响实时性；中断方式减少忙等，但每个数据或事件仍需要 CPU 执行处理。

**例题。** 设备每产生一个数据字就发一次中断。一次中断服务中 CPU 从接口取数据、写入内存并清除请求。设备连续产生 3 个字，若接口只有一个数据缓冲且不支持排队，会有什么风险？

**分析与逐步解答。** CPU 若未及时服务第一个字，第二个字可能覆盖缓冲中的旧值；即使发起中断，单一缓冲不能自动保存多个字。因此可能丢数据。需要保证服务速度足够、接口提供 FIFO/双缓冲，或改用 DMA 等批量方式。

**易错边界。** 中断解决“何时服务”的通知，不等于自动搬运数据。中断嵌套和优先级管理要确保现场保存正确；关中断过久可能造成丢失或延迟。
