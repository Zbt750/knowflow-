# 死锁

## 概念、定义与适用条件

死锁指一组进程中的每个进程都等待只能由组内其他进程触发的事件，因而永久无法推进。四个必要条件是互斥、占有且等待、不可强行剥夺和循环等待；打破任一条件可预防死锁。避免算法（如银行家）在分配前检验安全性；检测允许死锁发生后查找，恢复可撤销进程或抢占资源。安全状态不等于当前没有等待。

**例题。** 两进程各持有一个资源并请求对方的资源，资源均不可共享且不能抢占。指出资源分配图中的环及死锁条件。

**分析与逐步解答。** P1 持有 R1 并等待 R2，P2 持有 R2 并等待 R1，形成 `P1→R2→P2→R1→P1` 环。资源各只有一个实例时，环意味着死锁；同时满足互斥、占有且等待、不可剥夺和循环等待。若资源有多个实例，图中有环通常只能说明可能死锁，不能直接等同必然死锁。

**易错边界。** 饥饿是长期得不到服务但系统仍可能整体推进；死锁是相关进程集合停滞。银行家算法的“不安全”表示无法保证安全完成序列，不必然已死锁。

## 阅读总结

做题时明确模型与题设约定，保留关键中间状态并检查边界条件；练习从该节点关联题库获取，本讲解不重复收录练习。
