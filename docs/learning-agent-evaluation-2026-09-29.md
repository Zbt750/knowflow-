# 学习 Agent 场景评测

## 范围与使用

新增 `scripts/run_learning_agent_eval.py`，默认只运行协议替身，不产生模型费用。

```powershell
python scripts/run_learning_agent_eval.py
```

在用户明确同意发送隔离合成数据、演示题和内置讲解后才可运行真实模型：

```powershell
python scripts/run_learning_agent_eval.py --live --allow-synthetic-data --limit 8
```

脚本仅接受 `_test` 数据库，在随机 `agent_eval_*` schema 中创建全套表，连接的 search_path 不回退到 public。没有启动第二后端，不占用已有后端的单实例锁，不导入私人资料或开发学习记录。原始作答哨兵在模型请求前检查，不能发出；工具不会导出题目标准答案。

退出时删除本次 schema。被强杀时，下一轮仅回收格式、脚本标记都匹配且不持有活跃 PostgreSQL advisory lock 的遗留 schema，不扫描或删除其他评测、开发 schema。报告只保存在已被 Git 忽略的 `eval/reports/`；每轮使用唯一文件名，逐个场景保存进度，未完成运行显示 complete=false。

## 八个固定场景

1. 洛必达基础题；合成历史含客观答错与用户自评掌握的冲突。
2. 5 分钟，只做填空。
3. 5 分钟，只做计算；题库最短计算题 12 分钟，必须解释不足而非编题。
4. 节点只有原卷引用，没有在线题干。
5. 库里没有的考试范围，应说明或澄清。
6. 408 合成程序题，纸笔作答、人工对照，不执行代码、不宣称自动判分。
7. 今日唯一选择题已经加入，不重复安排。
8. 已有方案后要求少一点、只做填空、预算降到 5 分钟。

程序检查状态、实际题目、题型、基础难度、预算、去重、后端校验、确认前无业务写入。检查今日卷内容和学习状态不变化，不只比较记录数量。

报告保留真实工具结果与草案（仅合成数据），便于人工检查解释、限制说明和用户目标符合度。程序 PASS 不等于教学质量评分；尤其不能把协议替身通过当作真实模型能力，也不能把这 8 个简单合成场景推广到数学二和 408 的全部范围。RAGAS 四项问答指标仍在既有评测中，不拿它们替代任务执行评测。

## 本轮发现与修复

- 旧调用记录只计收到响应的轮次，失败请求被漏掉。现在记录每次尝试、错误码、异常类型、重试标志、耗时、上下文字符量、结束原因和 usage。字符量不是 token 估算，不存完整私人 prompt。
- `httpx.ConnectError`、超时和远端协议断连原来未正确标为瞬时错误。改为可重试；401/403 等确定性错误不重试。
- Agent 每轮至多重试一次，两次尝试共享原有 12 秒单轮上限，整个任务仍受 60 秒限制。失败请求可能已计费，未返回 usage 记为未观测，不记零费用。
- 报告区分模型轮次与请求次数，修改方案的首次运行也计入汇总。观察到的 token 之和不是未观测调用的完整成本；没有价格依据时不换算金额。

首次合成协议运行曾因夹具使用非法 state="learning" 而有 3 个场景失败，已改为现有枚举 stuck；这是夹具问题，不是业务缺陷，未修改状态枚举迁就测试。

首次真实模型运行约束通过 6/8，两个失败均在首轮连接上游时发生 ConnectError，未产生工具结果。失败报告保留；后续对同一组场景复测，不删坏例、不放宽验收预期。真实模型输出仍需人工核对，网络波动与评分变化不能当作质量改进的严格因果证明。

## 真实复测与新增坏例

第二轮完整 8 个场景程序检查通过 8/8，耗时 92.89 秒，含修改前初次运行共 9 次任务、41 次模型请求，观测到 87,001 total tokens；该轮没有失败请求或实际触发重试。因此不能把这轮改善全部归因于重试修复，也不能保证下一轮网络稳定。报告：`eval/reports/learning-agent-live-20260929T065416-c16309.json`。

逐条人工读回答发现两个场景原因被后端笼统消息替代，修为基于查询结果的明确说明；工具提示补充“不复习时节点列表为空且时间为0”，减少无效校验往返。后续4场景复测仅2/4，一个连接错误重试仍失败、一个连续调用工具用尽6轮；这份坏例保留于 `learning-agent-live-20260929T070019-b2b1fd.json`，不能被之前8/8覆盖。

最后一轮不提供工具，只要求模型按实际结果返回既定 JSON：有效草案可总结，没有有效草案应说明限制。轮次仍6、工具上限仍10、任务限时仍60秒。若模型不遵守最终协议仍按失败处理，不把未校验内容当方案。

再复测2场景时，短时填空通过，但“只有原卷引用”发生更重要的语义失败：模型未经用户确认改成了408程序题，实际题目和预算虽然有效，却不满足用户范围。报告 `learning-agent-live-20260929T070353-5b0a16.json` 为1/2，明确保留。

修复方式不是放宽期望：用户明确写出的节点名称/完整编号成为工具及草案校验的硬范围；允许所选父节点的后代，但不能擅自换到无关节点。更具体节点优先于课程背景，完整编号不按父编号前缀扩大；明确的新目标可改变旧范围。简称或含糊自然语言仍需查询、澄清，这不是任意自然语言范围的完整解析器。负向表达不被误认为正向范围锚点，但复杂排除条件仍需进一步结构化，尚不宣称完全支持。

该语义坏例最终单独复测通过1/1：返回 needs_info，诚实说明只有原卷引用、无在线题干，未生成程序题。报告 `learning-agent-live-20260929T070812-b80e23.json`。最终修复后没有再跑一遍全部8个真实模型场景；这些分轮结果不能拼成“最终版本全量8/8”。

## 收尾证据

- 后端全量回归 695 passed（97.04 秒）。其后补工具初始化失败立即终止任务的保护及1条回归；最终 Agent/评测/Provider 专项46 passed（18.86 秒），包含该最新改动，未虚报为已跑696条全量。
- 最终协议评测8/8，仅证明协议与程序约束；API/OpenAPI 漂移检查通过（34路径、20必需路径），差异格式检查通过。
- 这轮没有改前端、也没有重新跑全套Playwright，不沿用上一轮页面测试数量作为本轮证据。
- 五份真实报告覆盖相同8个场景的多轮复测，合计26次任务（含修改前方案）、103次模型请求、5次失败请求、2次重试尝试；观测到203,604 total tokens，5次请求缺usage，故总用量不完整、未换算费用。这些是本轮真实调用数，不是仅8次模型请求。
- 失败后保留原目标；连接失败提示稍后重试，不要求修改学习目标；鉴权失败提示检查设置。工具初始化异常不让任务一直停留在running。

仍待验证：更大的知识树、简称/复杂否定和跨章节目标、多次修改、不同上游模型、稳定性重复采样，以及和现有规则推荐的同任务对照。尚不能宣称Agent已经优于规则推荐或可覆盖全部考点。
