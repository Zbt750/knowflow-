# v4 文件场景有限复测：生成端不可用

本轮按用户授权，仅选用四份隔离合成讲义的三个目标场景：`file-exact`、`file-alias`、`cross-file`，计划上限为包含铺垫在内的4次问题请求。原始本地报告为`eval/reports/chat-file-focus-v4-20260930.json`，没有覆盖v3/v3.1报告。

实际执行了3次问题请求：`file-exact`和`cross-file`两个目标请求，以及`file-alias`的一次铺垫。铺垫失败后未继续发送该场景的目标问题，没有自动重跑整轮。三个请求均在生成阶段得到`generation_failed`，每个请求内置重试一次，共6次失败的生成尝试；没有完成帧、可观测usage或可评分回答。因此四项RAGAS指标**均为未评分（n=0）**，不是零分，也不能与v3.1质量均值比较。裁判没有机会对逐片段Precision作判断。

失败诊断在删除会话前取回：三条均为`diagnostic_status=recovered`、消息状态`failed`，实际证据快照分别有8、8、10块，说明检索及证据准备完成，故障位于生成阶段。调用记录当时只保存通用`generation_failed`，不能事后确定上游HTTP状态。当前本机不携带密钥对已配置域名`api.deepseek.com`作普通GET连通检查，得到`ConnectError`；配置显示模型为`deepseek-flash`、密钥存在且本地设置可读。综合看网络/端点不可达是强提示，但无法凭这些证据排除其它生成故障，亦不能验证密钥或余额状态。未发起额外模型探测。

隔离运行结束输出确认API、临时schema与索引移除，公共测试资料ID清单未变。本轮只用了合成资料，未发送私人资料或开发学习记录；未自动重试三场景。

为下一次故障定位，同步与流式生成调用记录新增严格白名单故障类别：HTTP状态、常见连接/超时异常、总超时、空回答、输出上限；不保存上游响应体、原始异常信息、密钥或路径。此改动发生在本次失败后，旧报告不能回填具体原因。

同时复现并修复SSE集成测试清表死锁：取消问答的异步包装任务不等于后台检索线程已退出。测试夹具现等待检索槽位释放后再`TRUNCATE`测试表，不修改业务库。初次专项56项、全量779项通过；补齐同步记录后的最终专项57项、后端全量**780项通过**；compileall与diff检查通过。未运行前端E2E。真实v4跨文件分类和单文件追问仍待模型服务恢复后、在新的有限授权下复测。
