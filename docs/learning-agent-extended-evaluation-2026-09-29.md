## 场景与真实结果

1. 连续两次修改：初始洛必达方案 → 五分钟填空 → 仍是这个知识点，五分钟选择题。
2. 无上文时说“那个知识点”：必须澄清，不乱猜。
3. 父节点内找题，并明确排除程序节点。
4. 要求三道不同填空题，而库内只有一道：不足则说明，不生成不足数量草案。

首轮报告 `eval/reports/learning-agent-live-20260929T092657-deaa83.json`：2/4，47.33秒，实际五次任务、18次模型请求，36,600 total tokens。多次修改在第一次修改后就失败，未执行第二次；不能把未执行阶段算通过。

- 修改时已经查到可用填空题，但两次 validate_plan 都因参数校验失败，没有可交付草案。旧错误只给笼统提示，未记录字段，无法事后确定是哪一个字段违规，不能推断一定是某个长度限制。
- 父节点查询只返回父节点；模型据其自身无题错误断言整棵子树无题，虽然子节点有五道在线题。
- 无上下文指代正确询问；三道填空需求正确说明只有一道，未编题或自动写卷。

修复后仅复测父节点排除场景：`eval/reports/learning-agent-live-20260929T093243-edb9a3.json`，1/1，11.75秒，五次模型请求，14,044 total tokens。方案含三道数学题，20分钟，没有程序题。

人工读回答仍发现解释缺陷：把被排除的程序节点说成“不存在”，草案理由也将未读取的程序题量写为零。约束 PASS 不证明自然语言解释忠实无误。工具新增明确的 excluded_nodes 信息和提示，系统提示区分“排除”和“不存在”；这项最终措辞修复未再调用真实模型验证。

两轮不能拼成最终四场景全通过。连续修改修复后尚未真实重跑，不能宣称已证实模型稳定完成三轮规划。

## 实际产品改动

- search_knowledge 返回最多八个匹配节点，加最多八个直接子节点，并标识子节点截断。展开有界，仅一层；父节点自身无题不代表所有后代无题，模型可继续按子节点名称查询。大型多层树性能和六轮预算仍待评测。
- 简单明确的“不要/排除/避开 + 节点名称或完整编号”排除其后代，查询与最终校验都执行排除。尚不支持任意复杂否定、取消旧排除条件的完整语义解析，不能宣称通用自然语言约束都已覆盖。
- 连续修改保留原始目标、最近目标和最近草案，不无限累积历史；新明确节点仍优先。后端约束与确认校验复用同一上下文构造。
- 参数校验反馈只返回字段与错误类型，不保存原始输入值，帮助模型修正而非重复错误。提示约束 rationale 长度及整型分钟；不是放宽参数校验。
- 提示词版本为 learning-task-v3。

## 评测工程改动

扩展集保存每个修改阶段的结果；修改没有执行完或中间阶段不满足约束，整场景失败。新增节点范围、排除范围、准确题数检查；summarize 统计所有修改阶段调用但不重复计算阶段快照。

修正合成夹具使用实际产品取值 objective_v1 / wrong，而非旧夹具的 objective / incorrect。没有修改业务枚举迁就夹具。

自动化新增：扩展协议集四场景六次任务、三道需求不足的草案被评测识别、父节点子节点可发现且排除分支不可查询、工具错误字段可修正且不回显输入、连续两次相对修改仍保留原知识范围。

## 尚未承诺

没有以这轮评测替代 RAGAS；没有证明 Agent 优于规则推荐；没有证明程序题可自动评分。题数要求这轮由模型正确遵守且由评测独立检查，尚不是后端所有自然语言数量要求的完整解析器。真实模型的解释仍需人工复核。

题数不足的说明曾建议“允许同一道题重复练习”；当前今日卷要求题目去重，不能把这个建议直接实现成同卷重复三题。可接受跨次复练，但模型必须解释区别。这是保留的解释适配问题，不因为 needs_info 状态正确就认定全部建议可执行。
