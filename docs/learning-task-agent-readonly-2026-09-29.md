# 学习任务 Agent 第一阶段：只读工具与草案

## 交付范围

在“内置资料”问答增加默认收起的“安排学习”入口。输入本次目标和5–240分钟预算，生成可修改、可取消的草案。“我的资料”不增加学习规划选项，普通知识问答仍走原流程，不自动将任何一句话强行分流为任务。

本阶段只保存任务及草案。**没有确认写入接口，不能生成或追加今日卷，不能改变作答、掌握度和毕业状态。**下一阶段才接入用户确认、实时重校验与写入幂等性。

## 真正的工具循环

Provider新增有界tool_turn，传递function工具定义，模型读取工具结果后决定下一轮。后端没有固定串行调用所有工具再让模型润色。可用工具：

- search_knowledge：按名称/编号定位活跃知识节点和路径，最多8个。
- get_learning_state：读取近期最多8条作答、客观依据、自评、待复测与毕业缺口；不发送原始私人作答内容。
- find_questions：读取最多16道活跃、有合理正时长的真实题目，标记已在今日卷及自动核对能力；不发送标准答案、解析。原卷引用只返回单独数量。
- read_lesson：读取系统内置讲解，最多4000字符，显式标注裁剪。不读取用户上传资料。
- validate_plan：校验已观察到的题号和节点、学习状态读取、重复、题目仍有效、今日已有题、预算、明确的限定题型/基础题约束及复习讲解可用性。时长来自数据库，不接受模型编造。

只有校验成功的服务端草案可交付。未校验的模型“方案”不会作为ready草案展示；模型可以提必要澄清。没有题可选时允许有讲解的只读复习草案，但明确警告题量不足，不假装给了题。

本阶段不新增RAG管线：已有检索、融合、问答保持原样；任务先使用结构化学习数据和内置讲解。允许范围内的RAG工具是后续评测后扩展，不重复实现三路召回。

## 状态与边界

created → running → ready / needs_info / failed；另可cancelled。

任务表保留goal、预算、上轮目标/草案、工具结果、状态和必要调用指标。每步用短事务保存，模型网络调用期间不占数据库连接。运行token防止取消或过期执行的迟到结果覆盖新状态。

最多6轮、10次工具调用、60秒执行预算；每轮网络调用另有最长12秒整轮限制。只允许白名单工具，参数使用Pydantic校验，禁止任意代码和SQL。超限不无限重试。单进程一次只运行一个任务。

重启后不会自动重放收费调用。超过时限的running任务标为中断，可由用户重试；恢复从头重新读取当前数据，不是从某个模型推理片段续写。ready任务重复run直接读已保存草案，不重复调用模型。

界面展示执行动作与结果，不展示内部推理或诊断日志。任务ID按会话保存于本地以便刷新恢复；切页不会主动取消服务端运行。不同会话的迟到响应不会覆盖当前任务。

问答初始化仍沿用“最近真实会话”的范围选择规则，不把独立任务写成空聊天。如果最近真实会话是“我的资料”，刷新后需要切回对应内置会话或内置草稿才能恢复任务面板。

## 尚不能承诺

- 没有7日/长期安排，不预测分数，不创建未来卷。
- 没有万能Agent、代码执行、多Agent、MCP或新向量库。
- 不声称原卷引用可在线作答，也不声称整个数学二/408题库已核验。
- 时间是题库预计时长，不是个人准确耗时；复杂自然语言约束不都可由规则完全理解，需场景评测和必要澄清。
- 没有多用户隔离体系；延续当前单用户应用边界，不能作为已完成的多租户产品发布。
- 模型必须支持兼容的function tool calling。不支持或返回不合协议时明确失败，不降级成假Agent。

## 可观测性和隐私

记录请求标识、提示词版本、每轮模型、耗时、已观测的token字段、工具调用次数及错误类型；上游不返回有效usage时标记未观测，不伪造消耗。完整私人资料不写普通日志；任务仅存必需、限定长度的工具结果和用户明确输入的学习目标。

当前rounds/calls统计已收到响应的模型轮次；在取得响应前失败或中断的请求可能没有usage，不能把缺失记录当作零调用或零费用。完整的跨重试成本汇总与历史任务列表不属于本阶段交付。
