# 桌面专用 PostgreSQL 生命周期（2026-10-01）

在 D-91 的同源前端/API 启动桥接上，新增应用自行管理的 PostgreSQL 原型。此次仍在源码布局中运行，使用本机已安装的 PostgreSQL 18 二进制，不是免开发环境的安装器；打包后内置资源定位、DLL/许可证、模型与后端 exe 仍须单独验收。

## 本轮实现

- `desktop/postgres.py` 固定专用用户目录 `LocalAppData/KaoyanStudy/postgres/cluster`，可显式指定隔离测试父目录。持久化目录所有者标识，拒绝接管不明集群、部分初始化目录、版本不一致、已有 PID 文件和被占用端口，不删除 PID 或用户文件来强行启动。
- 操作系统文件锁防止两个实例同时初始化；仅跟踪本次启动的集群路径、PID、启动时间与端口。退出前身份复核；身份变化时拒绝停止替代进程，不按进程名称或开发数据库端口杀进程。
- 管理员和应用账号各自随机密码。Windows DPAPI 加密凭据，写入前收紧 ACL。initdb 使用 ACL 限制的临时密码文件，结束清除；不把密码放在命令参数中。应用账号非超级用户，不能创建数据库或角色。
- initdb 使用 UTF-8 和 SCRAM 身份验证；数据库仅监听 127.0.0.1。没有 trust 认证、关闭 fsync 或远程监听的捷径。参考 [initdb 官方说明](https://www.postgresql.org/docs/18/app-initdb.html) 和 [认证规则](https://www.postgresql.org/docs/18/auth-pg-hba-conf.html)。
- `desktop/bootstrap.py` 验证专用库/账号，复用既有 Alembic 迁移和内置种子服务。首次导入知识树、演示题、原卷引用、讲解与内置参考材料，记录初始化回执。重启不再次执行种子 upsert，不改写用户练习或题目设置。
- 已有版本升级前调用 pg_dump，验证自定义备份可被 pg_restore 读取，再执行迁移；备份失败时不迁移。不认识的 schema/revision、已初始化但 schema 消失、无效回执均停止，不重建覆盖数据。
- 备份文件限制当前用户权限，但**没有内容加密**。此处只备份 PostgreSQL；不是包含上传正文、模型设置和索引的完整用户数据备份。没有上线自动恢复或跨机器数据迁移功能。
- 启动器新增显式 `--managed-postgres`、`--pg-bin`、`--pg-port`；与外部 `DESKTOP_DATABASE_URL` 冲突时拒绝。先保留 HTTP 端口再初始化，避免数据库准备完成后才发现 HTTP 端口被占。
- `--check` 仅校验文件/二进制版本与参数，不生成密钥、创建用户目录、连接或初始化数据库。普通 Web 路径和外部专用数据库模式保留。
- 发布资源清单补 Alembic 配置与白名单种子脚本，不扩大到整个 scripts、私人数据或评测目录。清单仍标 `installer_ready=false`。

## 源码模式用法

先构建前端。资源目录应为当前完整项目根：既有种子/讲解服务尚依赖源码模块旁的 seed 目录，不能仅复制 dist 和数据库程序就认为发行布局可用。安装器阶段必须测试冻结后的资源解析。

```powershell
# --resources 为项目根绝对路径，--pg-bin 为审核过的 PG18 bin 绝对路径。
python scripts/run_desktop_backend.py --resources "<项目根绝对路径>" --managed-postgres --pg-bin "<PG18-bin绝对路径>" --check
# 首次真正启动会在用户目录初始化专用数据库，与开发 .pgdata 无关。
python scripts/run_desktop_backend.py --resources "<项目根绝对路径>" --managed-postgres --pg-bin "<PG18-bin绝对路径>"
```

默认 HTTP 18750、PG 18760；模型密钥不继承开发配置。内置材料初次为待索引状态；模型资源未预置时检索不可用如实降级，不能宣称首次启动就能离线检索全部资料。

## 测试中发现的真实问题

1. Windows pg_ctl 的持久子进程继承捕获输出管道，服务器虽已就绪，subprocess 仍等待管道关闭，超时回收也可能阻塞。启动/停止控制命令改为 DEVNULL，服务器写独立日志；补断言与真实启动回归。失败运行只停止已核实的临时集群，未触碰开发 PostgreSQL。
2. libpq 的 `service=''` 不是“禁用 service”，而是查找名称为空的服务，导致连接失败。移除空 service 参数，继承 PGSERVICE 时拒绝连接，子命令清理 PG 环境变量；不依赖修改其他线程的环境。
3. 补全初始化回执版本和 schema 存在性检查，防止错误回执造成静默跳过种子或误重建。

## 验证范围

真实测试用独立临时集群和随机端口，不使用开发库或共享测试库承载新增桌面数据：首次创建、完整迁移/种子、DPAPI 凭据、最小角色权限、重复启动拒绝、备份，以及恢复到同一临时集群内新库核对保留行；随后重启原库验证保留行和不重复种子。退出后确认 PID 文件消失与端口释放。

同一测试接入现有 API/前端托管：health、无配置模型设置、资料列表及五条页面路由可访问。检索栈替身关闭，未调用模型、未下载模型；该检查不等于桌面真实检索性能测试或本轮新浏览器截图验收。单元测试另外覆盖备份失败阻断迁移、陌生 schema、端口冲突、启动后失败清理、身份变化拒绝停止和只读预检。
