## 维度与边界

映射版本 `question-type-role-v1`，证据视图版本 `capability-evidence-v1`。

| 维度 | 使用的已有题目元数据 | 能证明的范围 |
| --- | --- | --- |
| 概念与条件 | 单选、多选题型 | 仅所做题最终选项的可靠证据，不等于完整概念理解 |
| 最终结果计算 | 填空、计算、明确的程序输出/执行结果题型 | 仅最终答案，不评价推导过程 |
| 变式与应用 | 上述客观结果题的变式标记或 variant/comprehensive 学习角色 | 指定题目的最终答案证据，不代表所有综合应用都掌握 |
| 证明与讨论 | proof/discussion | 当前无可靠过程判题，不会由数值答案、完成或 AI 审阅确认 |
| 算法与程序 | program/algorithm/code；408 默认展示缺口 | 当前无可靠代码执行/过程判题，不把伪代码审阅当通过 |
| 其他作答形式 | 未识别的题型，存在时才展示 | 保守未知，不猜测其能力映射 |

所有数学节点默认前四项，408 另展示算法与程序。属于适用范围内的粗粒度元数据映射，不是人工核验过的完整学科能力清单；不从题干、节点名称或大模型猜标签。一个变式题可以落在两项，维度不能相加当作两道不同题。

明确执行结果题型仅预留分类入口，没有新增这类在线题或判题器。现有 `available_grading_method` 仍仅支持经过核验配置的单选和有限数值最终答案；未来新判题方法要先明确适用范围，不能只因为题型名称命中就获得可靠证据。

状态只有：

- **尚未验证**：没有有效独立证据或适用作答记录。不等于不会。
- **证据有限**：近期有作答，但没有当前有效的独立确认，可能是辅助完成、猜对、未判定、自述或旧记录。
- **已有独立证据**：至少一道不同题有当前有效的、系统未观察到辅助的独立最终答案确认。不等于全面掌握或毕业。
- **待复测**：该维度有当前可可靠核对题目的待复测记录，优先于已有成功证据。其他题的有效确认保留。

不设置武断的 87.3% 分数，也不新设毕业阈值。“独立”仍仅是界面观测，不是监考证明。证明/程序维度当前不会出现可靠过程确认。

## 有效证据如何取得

同时满足当前 objective_v1 窗口中的 confirmed/objective_final 条目、相同题目与提交时刻的不可变回执、已知 P2 序列版本及允许的独立成功类别、未辅助、不是猜测/完全没思路、当前内容哈希匹配、当前题目仍活动且比较器可用。自述和原卷引用不计入，题目内容修订后不直接沿用旧成功。当前窗口外的历史成功不重新捞回充数。

P3 的新回执增加当次 `question_role` 元数据，但不改变 P2 哈希算法或旧回执。变式标记原已被哈希保护；通过学习角色映射的“变式与应用”还需当次角色与当前角色相同。P2 旧记录没有角色时不能后来改成综合题来获取应用证据；旧记录不回填。不影响仍可核对的基础最终答案证据。

近期统计最多 100 条，并公开 `history_truncated`；当前确认窗口的回执核对另查最多 200 条，超限公开 `confirmation_lookup_truncated` 且保守不计独立确认，不假装全量核对。当前题目/版本/历史不能支持的窗口证据计入 `excluded_confirmation_count`；无法映射到活动题目的待复测标识另计，不生成虚构题目。

失效确认计数只统计原本声明 confirmed 的条目，弱证据、失败和同题的有效重复回执不冒充失效确认；独立题量仍按不同题去重。旧自评 basis 的待复测字段不晋级为客观复测证据。

## Agent 接入

`get_learning_state` 复用同一后端投影，返回维度 key、label、status、证据范围及在线题、可可靠核对题、独立题和待复测题数量。不重复输出每行长解释、原答案、标准答案、独立题 UUID 列表或私人资料。UI 和工具可以核对相同计数；工具侧只精简表示，不另算掌握。

`find_questions` 增加 `capability_keys`，模型可看到真实题对应的粗粒度维度；没有新增写工具或万能推荐器。学习任务提示词从 `learning-task-v4` 到 `learning-task-v5`：优先考虑待复测和用户目标，不把未验证说成不会，不把最终答案说成过程正确，不按多维度重复安排同一道题。程序继续执行范围、时间、题目去重、草案校验和确认事务。

普通 RAG 的检索、Prompt 与模型配置不变；P0 原报告不改写。本轮不调用真实模型，不能据离线回归宣称真实规划效果或 RAG 分数上升。真实模型闭环对照仍留给后续获准评测。

## 浏览器回归暴露的索引生命周期缺陷

第一次全量浏览器回归中，隔离向量库在准备进程内计数为 17，但测试后端新进程打开时失败，health 为 retrieval=unavailable、worker=stopped。4 条真实问答用例失败，随后主动中止；新增 3 条 P3 页面用例在该次已通过，但整轮不能计为通过。失败截图与 trace 保存在 `eval/reports/capability-evidence-p3-20261001/playwright-output/`，没有用重跑覆盖。

检查发现原 `ChromaVectorStore.close()` 将 `reset()` 当资源释放方法。本机 Chroma 1.5.9 提供公开 `Client.close()`，按共享 System 引用计数关闭；reset 是数据操作，不是 close。改为调用公开 close、保持幂等；构造失败也释放已取得客户端。旧版无公开 close 时只断开引用并回收，不重置数据或清理全局共享缓存；这类旧版本不承诺进程结束前彻底释放句柄。

新增 4 条回归验证：关闭绝不 reset（含无 close 旧版本）、重复关闭、新进程重新打开后仍可计数/检索，以及关闭一个共享客户端不影响另一个。均使用临时合成三维向量，无 embedding 下载或外部模型请求。

浏览器启动门禁改为同时检查隔离离线 Provider、数据库 connected、retrieval ready 和 worker running，依赖异常时立即拒绝跑浏览器，而不是拖到逐题超时。回收仅停止本次启动、命令与端口匹配的 Python launcher 和直接子进程，不按端口杀开发服务。
