# 最终答案提交与学习证据闭环

## 功能范围

白色简约界面不增加新页面。专注/全卷模式可在纸上作答，只记录最终答案或关键结论。

- 已核验的单选题：比较有效选项。
- 已核验的单一数值填空/计算题：精确比较整数、十进制小数、分数；例如 0.5 与 1/2 等价。
- 证明、讨论、程序题，以及未核验题目：只记录作答，显示暂无法自动判定，不猜测正误。
- 空白答案：记录未作答，不当成正确，也不直接改变掌握度。
- 近似误差、符号公式、单位、多空答案、多小问、代码执行尚不支持。0.333 不等于 1/3。

首批三道演示题显式核验；其余题不能仅因为存在 correct_answer 就开放判题。计算题只判断最终数值，不能声称推导过程正确。

## 接口与数据

- POST `/api/practice-items/{item_id}/answer-submissions`：保存不可变 QuestionAttempt 和 LearningEvent，更新练习项完成进度。不调用掌握度状态机，不累计毕业次数，不清空已有证据。
- POST `/api/practice-items/{item_id}/answer-reveal`：前端读取答案时记录首次查看时间；提交后查看不会反过来污染已保存的判题快照。
- 原 GET answer 仍纯读取，原 self-assessments 保留。新旧动作不可复用同一个幂等键。
- 同一动作重试使用同 key；不同题目或改变答案后复用同 key 返回 409。已完成项换 key 不产生第二份记录。未来复练应安排新的练习项。
- 每条新作答保存实际参考答案、核验配置、判题方法/版本、结果、提交时间和查看记录；历史标准答案变化不改写旧判题事实。
- self_grade 允许空值，历史自评不变。知识树能展示最终答案结果与辅助作答标记。
- 计划、练习项按统一顺序锁定，避免并发完成最后两道题时漏更新整卷状态。

“未记录查看解析”不等于考试监督下的独立作答：旧 GET 接口、外部资料和用户线下行为无法完整观测；既有查看历史也不能凭空重建。快照标注 tracked_interface_not_proctored，不作为严格独立作答的证明。
