# 照片录入过程：实现范围与验收

## 用户流程

今日学习的计算、证明、讨论/主观题，在“检查我的过程”内增加默认折叠的“从照片录入过程”。选择本地照片（移动浏览器可提供相机入口）后本地预览；勾选发送同意，再点击识别。模型只转写，不解题或判断对错。识别结果可编辑，用户核对后点击“确认并填入过程”；已有文字须另外确认替换。最后仍需主动点击原来的辅助审阅按钮。没有自动提交、自动跳题、自动判分或更新掌握度。

图片提示、公式、程序都可能识别错；不可辨认处要求模型标注，不能保证模型严格遵守。最终答案判题仍走既有有限判题器和核验配置，不把转写结果当作客观证据。取得过程辅助建议后的作答仍遵守原有辅助证据规则。

## 模型配置

设置页新增折叠的“拍照识别模型”，可以独立填写兼容 Chat Completions 的接口地址、模型和密钥，也可复用当前支持图片的问答配置。默认未保存独立配置时复用问答配置，**不会自动检测或宣称任意问答模型支持图片**。配置完整不等于识图准确率已验证。

DeepSeek 官方文档已列出 deepseek-flash 的图片输入；先前把它一概视为纯文本模型的说法已纠正。兼容中转服务是否开放相同能力仍需验证：[官方视觉指南](https://api-docs.deepseek.com/guides/vision/)、[模型列表说明](https://api-docs.deepseek.com/api/list-models/)。

独立配置使用 vision-model-settings.bin，与问答配置分离；Windows 复用 DPAPI 加密，不返回密钥，不写浏览器存储。非 Windows 无可用安全密钥存储时拒绝落盘秘密，而非明文保存。配置读取或保存受既有本地访问和 CSRF 保护；刷新保留未保存输入。损坏独立配置停用识别，不静默改用另一密钥。独立文件及临时文件已加入 .gitignore。

## 接口与隐私边界

- GET/PUT /api/settings/vision：独立配置，不修改问答设置。
- POST /api/practice-items/{item_id}/recognize-work：multipart file、consent，校验已有题目和允许题型。
- 文件内容实际校验：静态 JPEG/PNG/WebP，最多5MiB，单边4096像素、总像素1200万；重编码 PNG，移除 EXIF/位置等元数据，透明背景转白。
- 单进程最多2个并发识别，网络及总等待最多60秒；不自动重试、不跟随 HTTP 重定向、不接受外部图片链接。
- 只接受明确 stop 的非空完整转写，不静默裁剪超过4000字符、被截断或被过滤的内容。
- 本项目不把图片写入业务数据库或上传目录；内存请求和底层 multipart 临时缓冲仍可能存在，不能称为绝对“不落磁盘”。同意发送后模型服务接收重编码图片，其保存政策不受本项目控制。
- 返回模型名、耗时和可观测 usage；未返回 usage 时为 null，不估算实际费用。当前不保存完整视觉调用快照或识别历史。
- 用户取消会停止前端等待；不能保证撤销上游处理或费用。切题/卸载/替换文件时旧请求不得回填另一题。
