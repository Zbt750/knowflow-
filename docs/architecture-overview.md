# 自适应考研知识库：架构与数据流

> 本文依据当前代码与 Phase 5 验收路径概述，不是对所有供应商、容器或生产规模的背书。Phase 5 Docker 容器启动和真实付费模型链路未完成验收。

## 系统边界

项目面向考研数学二与计算机 408 学习者，是单用户本地自适应学习应用：帮助学生理解知识点、练习巩固、发现薄弱环节，并据真实学习记录安排后续复习。Vue/Vite 前端通过 HTTP/SSE 调用 FastAPI；后端服务层负责知识树、题目、练习、学习事件、检索和 Agent 工具；PostgreSQL 保存业务事实，Chroma 保存可重建的资料向量索引。原始资料正文及可定位区间仍由 PostgreSQL/本地存储的权威内容支持，向量索引是派生数据。

```text
用户浏览器
  ├─ Vue 页面：知识树 / 今日学习 / 资料库 / 问答 / 学习任务
  └─ HTTP 与 SSE
       ↓
FastAPI routes
  ├─ 练习、答案提交、解释与学习历史服务
  ├─ 今日计划与学习 Agent tools
  ├─ 资料解析、分块、检索与引用服务
  └─ 问答服务与模型 Provider
       ↓
PostgreSQL（题目版本、计划、Attempt、LearningEvent、KpState、资料元数据）
  ├─ 本地文件存储（上传资料）
  └─ Chroma（由资料内容构建的向量索引）
```

## 题目版本与学习证据

`Question` 是稳定身份；`QuestionVersion` 保存不可变的题干、选项、答案、解析、题型及判题配置版本，Question 当前指针用于新建练习。历史 `PracticeItem`/作答应依其绑定的版本解释，不能因为后来修订当前题目而重写旧作答的语义。审核事件应与内容版本或内容哈希绑定。

用户提交答案后，练习服务依据该 PracticeItem 绑定的题目版本调用相应 grader，保存 Attempt 和相应 LearningEvent；能力/KpState 投影消费可用证据。AI个人题与公共正式题有不同归属和资格边界：运行时个人生成题可以作为练习，但不能被伪装为公共正式毕业证据。

## 毕业题集

每个具体考核知识节点具有版本化的有限题集快照，集合成员绑定题目/题目版本。完成该节点适用题集的真正完成规则后，节点可毕业；已开始学习的旧题集绑定需保持稳定，新发布版本不可静默扩大旧学习义务。具体完成语义由掌握/毕业服务计算，本 Phase 5 没有修改毕业算法或历史状态。

## 今日学习和 Agent

今日学习先生成推荐/草案，用户确认后才创建或调整今日试卷。Agent 工具从服务端读取库存、学习进度、错题与任务事实，再返回建议；Agent 文本本身不是数据库事实，也不应凭空宣称完成了学习或毕业。计划、题目实例、提交记录继续走同一学习数据链，不为个人题复制一套 Attempt 系统。

```text
历史学习事实 + 当前库存 + 节点范围
             ↓
       Agent/Planner tools
             ↓
    推荐草案（原因、候选任务）
             ↓ 用户确认
       DailyPlan / PracticeItem
             ↓ 作答与判题
 Attempt → LearningEvent → 能力/节点状态
```

## RAG 资料链路

```text
上传资料 → 安全解析 → 按标题/内容切块并保留定位
       → 保存正文/元数据 → 生成本地 embedding → Chroma 索引
       → 问题检索（向量与词法信号融合）
       → 仅把检索命中的资料片段作为资料回答依据
       → SSE 展示回答与引用，引用可定位回来源
```

删除/重建行为需保持正文、资料元数据与派生索引的生命周期一致；删除资料后不应继续提供其引用。Phase 5 用数学和 408 测试资料在隔离库生成 19 个 chunk，部分上传、索引、搜索与重建 UI 流程通过，但引用/删除全闭环仍需补测。

## AI问答与来源区分

问答服务可使用资料检索增强，也可使用模型通用知识。回答中的“资料依据”必须来自当前检索命中的 chunk，并展示来源定位；通用模型知识不能伪装为项目资料引用。当前 Phase 5 浏览器使用离线固定 Provider，验证的是 UI/服务契约的部分路径，不是 DeepSeek/OpenAI 在线模型回答质量。

## 运行时组件

- 本机开发：PostgreSQL 项目实例、FastAPI（8000）、Vite（5173）。
- Docker Compose 候选：Nginx/Vue 前端（8080）反代 FastAPI，PostgreSQL 与资料存储位于容器网络/卷中。
- 本轮实际执行的 E2E：系统 Chrome + 隔离 PostgreSQL（59241）+ 本地离线模型 Provider。

Compose 的 PostgreSQL 镜像目前为 16，而真实开发库为 18.4；容器启动尚未验收，数据库版本/数据卷迁移策略需要先解决。部署步骤见 [Windows 部署指南](deployment-guide.md)。

## 面试问题与参考回答

**1. 为什么同时有 Question 和 QuestionVersion？**  
Question 标识“这道题是谁”，QuestionVersion 标识“某次练习实际看到的内容是什么”。题目修订只更新当前版本指针并追加新版本，历史 PracticeItem/Attempt 仍绑定旧版本，因此历史判题和解释不随题面更新漂移。

**2. 为什么不能用 AI 生成的题直接作为毕业证据？**  
个人运行时生成题的用途是个性化练习，不等于经过公共正式题审核。系统在服务端按题库归属和审核证据决定资格，不能通过改来源字符串或模型自评把个人题变成正式题。

**3. 一份 RAG 引用如何保证可追溯？**  
资料先解析并切块，chunk 保留资料身份和正文位置。检索返回命中的 chunk；回答引用只允许关联本次上下文中实际命中的资料片段，并向用户展示出处与定位。向量索引是派生索引，原始正文才是权威来源。

**4. 为什么需要 PostgreSQL 和 Chroma 两种存储？**  
PostgreSQL 保存结构化业务状态、资料正文/元数据和学习证据；Chroma 只负责向量近邻检索，可从权威资料重建。不能把 Chroma 当成唯一资料备份。

**5. Agent 怎样避免凭空安排学习任务？**  
Agent 通过受限服务端工具读取真实节点进度、题库库存、错题和计划事实，再提出任务草案；用户确认后才写入/追加计划。模型自然语言不能直接成为完成证据。

**6. 什么是“真正完成一道题”？**  
判定依赖该题绑定版本上的提交、辅助状态和判题结果。看解析后立刻答对不应冒充独立掌握；历史做错也不是永久惩罚，后续可信独立验证可体现学习进步。

**7. 如何处理题目答案修改？**  
新增 QuestionVersion 并绑定新的审核证据。旧计划继续读旧版本，新计划读取当前版本；若已有学习实例绑定历史集合，发布新集合不能静默扩大它的要求。

**8. 本次验收能否说产品已经发布就绪？**  
不能。前端类型/单元测试/构建通过，但后端有 69 个失败和 6 个错误、E2E 有 70 个失败；Docker 真实启动也未验证。必须修复失败并在可用 Docker 环境复测后再签发布候选。

**9. 为什么本地模型测试使用离线 Provider？**  
本轮验收重点是应用交互、数据隔离和服务契约，不授权新增付费模型请求。离线 Provider 不证明真实供应商模型可用，也不能作为生成答案正确或模型质量的证据。

**10. 真实库发布前最重要的数据安全措施是什么？**  
确认目标库身份、创建并验证可恢复备份、在恢复副本预演 schema/数据变更、逐项对比用户历史指纹，并将 migration 与题库导入分成可审计步骤。不能用隔离库 dump 覆盖真实学习历史。
