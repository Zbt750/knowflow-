# 自述边界与真实模型验收 · 2026-09-30

## 产品规则

- 有可靠自动判题配置的题目只提供答案提交和跳过，不再显示旧自评替代入口。
- 未核验的开放题和原卷任务保留默认收起的「自行对照记录」，选项为独立完成、部分完成、未完成。记录练习进度，不构成机器判题或毕业确认。
- 节点自述熟悉程度、作答信心与机器结果分开。新事件 `practice_self_reported` / `node_self_reported` 只更新辅助反馈，不改变已有确认窗口、掌握状态、历史基础确认或复测安排。
- 旧事件规则保留以支持历史审计；没有批量删除学习记录或把旧毕业状态冒充新客观毕业。可靠独立正确答案仍走已有客观提交服务。
- 旧 `graduate-demo.cmd first/retest` 通过代点自评准备毕业证据，不再适用；入口在连接数据库前拒绝执行。`show` 可只读使用。

## 有限真实模型验收

专项授权仅限隔离合成数据：最多 8 个 Agent／开放题审阅场景与 4 次 RAG 问题请求。专项已使用 4 次 Agent 任务、4 次文字审阅与 4 次 RAG 请求；专项没有自动重跑，没有发送私人资料或开发学习记录。

**费用边界纠正：**收尾发现原有普通 E2E 仍继承真实模型配置，若干聊天用例也发生了模型调用，超出上述专项调用上限；已停止那次重跑，不能把此前 E2E 说成免费替身测试。浏览器报告不含完整上游账单，无法精确重建额外费用。随后新增只允许 test 环境的 `scripts.e2e_backend` 协议替身，覆盖同步、流式和意图分类，工具调用意外触发时拒绝执行；子进程用占位设置覆盖 dotenv，不修改开发设置。普通测试入口校验离线模型标识才运行浏览器，真实质量评测继续单独授权。新增离线网络禁用与 dev 环境拒绝两条单测。

## 测试隔离及剩余边界

一次全量后端与 RAG 隔离服务并行造成数据库实例锁冲突及公共测试夹具变化，首轮回归失败属于该环境冲突；已停止评测服务后串行跑完整后端通过。RAG 清理提示公共测试资料清单变化，不能将其记录为「测试库完全未变」；隔离服务和 schema 已回收，开发库未发送给模型。后续必须串行执行共享同一测试库的全量测试、E2E 与评测。

本轮不把内容数量当覆盖证明：仍只有少量核验在线题，408 主要是原卷引用。完整题干与可靠答案核验、Precision 专项复核、更多固定评测样例、图片审阅及安装包是独立待办；不得虚构题目或以 Agent 完成替代安装验收。
