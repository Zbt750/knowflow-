# 多文件问答缺陷修复与真实复验（2026-09-27）

## 实施范围

针对 D-56 的真实评测缺陷修改业务代码，而非仅修改评测分数。保留原始评测报告与原始回答，不覆盖历史结论。

- 文件名匹配按独立提及位置保留所有目标，不再只保留全局最长标题；支持保守的讲义简称。多个不同文件可比较，真正同名冲突仍需澄清。
- “这两份”等指代从用户历史解析文件范围；指定多份文件概述/比较时读取各文件的当前活动索引正文，不以普通相似度 top-k 代替整份阅读。
- 全文读取仍受合计 50 块、24000 字符的安全边界限制，超过范围明确提示缩小范围，不伪称读完。某个目标文件活动正文缺失也明确提示，不悄悄只读另一份。
- 已指定文件范围时跳过额外模型意图分类；普通主题检索仍保留动态覆盖策略。
- 明确未知文件不借另一份文件代答。近似标题只提供候选并要求确认，不自动读取相似文件；确认正确文件后才读取。
- 提示约束保留样本对象、单位及数学前提，要求跨文件分别解释并分别提供实际例子。资料不足时的常识补充仍与资料依据分区，不伪造资料引用。
- 引用兼容层额外识别 `[ C1 ]`、`[C 1]` 等空格格式，仅转换本轮确实存在的编号，代码块/行内代码不改；未知编号不能生成来源卡。
- 保存准备阶段耗时、首段模型正文等待和模型生成耗时，支持区分检索慢与上游模型慢。

官方 DeepSeek `deepseek-flash`/`deepseek-v4-pro` 调用采用 `reasoning_effort=low`，保留推理，分类器关闭思考避免48-token分类预算被推理消耗。严格限制官方主机与已知型号，其他兼容端点不附加参数。官方 API 文档说明默认推理强度为 high：<https://api-docs.deepseek.com/api/create-chat-completion/>。此调整不保证每次响应更快，须以实际等待记录判断。

## 验证方法

首轮34次真实问答中，多文件范围、例题、多轮追问和样本单位缺陷已不再复现；仍捕获一次空格引用格式无法识别，随后补上转换及回归。数学详细回答的文本检查曾把 LaTeX 分数误判为缺失，经实际回答复核确认正确。这些记录保留在本地 `eval/reports/multifile-depth-after.json`。

最新问答相关隔离回归139条通过，前端单测24条通过，typecheck通过。此前中间版本另有213条隔离回归通过；不得把不同批次简单累加成独立用例数量。数据库验证使用随机独立 schema，不操作用户历史，真实评测清理仅针对自建进程、schema与临时索引。

## 已知边界

提示约束不能替代数学定理验证或完整的语义裁判；本次不产生新的 RAGAS 四项评分，也不据此声称100%准确率。长回答仍可能等待上游数十秒，本轮重点是覆盖完整、证据范围正确、来源可校验，并把性能瓶颈变成可追踪记录。
