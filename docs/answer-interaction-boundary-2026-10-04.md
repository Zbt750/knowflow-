# 题型作答与毕业证据入口修正（2026-10-04）

## 修正的问题

旧界面仅按 `answer_grading_method` 是否为空显示“自行对照记录”，把“题目待核验”和“题型需要主观对照”混为一谈，导致未核验选择、填空和计算题都出现自评入口。

现在两种视图共用 `frontend/src/lib/answerInteraction.ts`：

- 选择、填空、计算等最终答案型题目直接提交，不因没有可用 grader 而出现自评入口。
- 证明、主观题、讨论、算法、程序及原卷引用，在没有可用 grader 时才允许默认收起的自行对照。
- 正式题型目前以已有后端枚举为准；预留类型分支不等于增加了程序执行、多选或新题型 API 支持。
- 待核验转录题明确提示“答案待核验”，其他未具备判题能力的题只说“尚未启用可靠判题”，不臆测其未支持原因。
- 客观题的按钮统一显示“提交答案”，填空和计算的输入提示不再误称证明／程序题。提交未知结果仍显示未判定，不伪造对错。
- 开放题的自行对照、辅助审阅不计入客观毕业确认；解析、重试和后台尝试证据保持不变。
- 知识树的默认折叠毕业要求解释“考核要求不代表题库已具备核验能力”。包含当前未支持题型的要求明确提示可靠确认途径缺口，不静默放宽规则。

## 内容与可靠判题边界

本次没有修改题库、标准答案、核验标记、毕业策略、数据库迁移或后端判题服务。此前只读统计为 52 道有效题、0 道已核验判题配置，因此本次界面修正**不代表 52 道题已经能可靠自动判题**。

启用对应题目判题仍需走现有内容核验流程，确认答案、题干、来源、映射与 grader 配置。仅生成了答案、用户说暂未发现问题、隐藏了自评入口，都不能替代内容审核。

## 验证

类型检查、构建通过，前端单元测试 **14 文件 / 66 条通过**。新增题型分流单测覆盖有无 grader、待核验与未支持区别、未知题型和开放题。

完整隔离浏览器回归结果 **153 passed / 1 failed**，报告：`eval/reports/stage1-20261004/answer-type-boundary-v1/run-report.json`。失败是整卷刷新测试仍断言旧自评提示，实际作答状态已显示；将断言改为作答状态后，导航与提交专项 **13 passed / 0 failed**，报告：`eval/reports/stage1-20261004/answer-type-boundary-navigation-v2/run-report.json`。没有再次运行整套，不宣称修正后全量重新通过。新增六个待核验场景（选择／填空／计算 × 专注／全卷）全部通过，验证直接提交、无自评、未判定反馈与毕业边界；旧错误码自评夹具改用开放题，整卷刷新回归改走客观答案提交，不保留已撤销的客观题自评入口。

测试仅使用隔离库及离线模型替身，不调用真实模型、不使用开发学习记录。此前资料页前进／后退偶发失败仍是已知问题，没有在本次修复或删掉该用例。
