# 跨文件首轮输出预算：隔离合成数据探索性对照

用户授权继续下一步后，本轮只使用原四份隔离合成讲义，对同一道 `cross-file` 问题分别运行一次首轮输出预算 4000 与 6000；每次只发 1 个问题请求，照常运行四项 RAGAS 裁判。报告分别为 `eval/reports/chat-cross-file-budget-4000-20260930.json` 和 `eval/reports/chat-cross-file-budget-6000-20260930.json`，不覆盖历史报告。两次隔离 API、schema、向量索引均已清理，公共测试资料未变；未发送私人资料或真实学习记录，失败未自动重跑整组。

新增 `--baseline-v3-1 --cross-file-budget {4000,6000} --limit 1` 入口：只选固定的 `cross-file` 场景，评测层还强制最多一次问题请求。覆盖预算只注入隔离后端子进程及当次报告配置；不改 `backend/config.py` 默认值或本地用户模型设置。其他模式混用在连接数据库前被拒绝。

两组的固定样例哈希相同，实际交给模型的 10 块证据正文与顺序完全相同；模型、提示词版本、重试预算 8000 和其余报告配置一致。主要观测如下：

| 首轮预算 | 完成原因 | 重试 | 总耗时 | 首次可用正文 | 答案生成可观测 token | Faithfulness | Answer Relevancy | Context Recall |
| ---: | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 4000 | stop | 0 | 17.4 秒 | 约 16.1 秒 | 5388 | 1.000 | 0.465 | 0.667 |
| 6000 | stop | 0 | 15.6 秒 | 约 13.9 秒 | 4795 | 0.875 | 0.740 | 0.667 |

两次都在**首轮正常结束**；此前同题 4000 预算曾达到上限并重试至 41.6 秒，说明长等待不是每次稳定复现。6000 这一次略快且用量更低，是不同生成内容和模型随机性的共同结果，不能归因于提高上限。人工对照合成原文，两份答案均将“数据库持久化、重启恢复”归为共同要求，列出阶段说明 A–E/G 与 F 中独有的部署配置，以及补充文件的桌面安装边界和至少三次备份；引用编号均对应本轮实际证据。没有发现这两份答案因首轮预算产生可确认的事实遗漏。

两组 Context Precision 仍为 0；逐块理由延续了“单块不能独立完成两文件比较，故无用”的口径问题。Answer Relevancy 的裁判反推问题在 4000 组三次都缩成“部署与数据库持久化要求”，漏掉用户要求的各自独有比较；6000 组反推问题不同，分数随之上升。Context Recall 两组均 0.667，与人工检查到的主要要点齐全并存，不能把这组 RAGAS 波动直接解释成预算提升了回答质量。

**取舍：保持全局首轮 4000、重试 8000 不变。** 这只是每组一次的探索对照，没有足够样本证明提高预算能降低总体延迟、成本或错误率。下一步更值得先处理评测对多块组合答案的适用性，并在真实产品需要的同类问题上积累截断／重试分布；任何新增模型调用须重新限定资料与次数。

离线入口与评测相关测试 23 项通过；没有运行后端全量或前端 E2E，本轮没有改问答业务流程。
