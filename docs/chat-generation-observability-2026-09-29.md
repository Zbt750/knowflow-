# 问答生成调用记录

## 本轮范围

复用消息 metadata，不新增数据库表、主页面或外部日志平台。`generation_trace` 记录请求 ID（回答消息 ID）、配置模型、提示词版本、同步/流式方式、每轮耗时、预算、结束原因、状态、错误码、重试次数和可观测 token 用量。

范围明确为 `answer_generation_only`：不包含检索意图分类、Agent 工具循环或其他辅助模型调用，不能作为整个应用的总费用。每个请求单独创建追踪对象，用 ContextVar 把每轮记录传入异步读取任务，不在 Provider 上保存可被并发请求覆盖的 usage。

## 用量语义

- `usage` 保持最终回答这一轮的上游计数；未返回有效计数时为 null。
- `generation_trace.calls` 分别记录所有生成轮次，包括空回答、截断重生成和故障轮次。
- `observed_usage` 只累计实际观测到的计数；缺失轮次不能按零消耗理解。
- `total_usage_complete` 仅当每轮都返回 total_tokens 才为 true。
- 输出预算单独叫 `output_budget`，不再把 max_tokens 当作 usage 存入。
- 无模型直接答复保留零轮记录，不声称调用了模型。

流式解析支持独立的尾部 usage 帧，即 choices 为空也读取计数。模型 stop 帧后继续读取尾部用量；不把 reasoning_content 发给用户或保存到追踪中。

`LLM_STREAM_INCLUDE_USAGE=false` 默认保持兼容请求不变。确认所配置端点支持后可设为 true，发送 `stream_options.include_usage`。本轮没有修改真实配置或用收费调用验证端点支持情况；端点主动返回 usage 时，即使开关关闭也会记录。

## 隐私与失败

普通追踪不保存问题、提示词正文、私人资料、推理内容、密钥或上游响应体。usage 只接收非负整数计数，结束原因仅接收已知枚举，其他值标 unknown。生成重试日志不再打印问题摘录。

成功、失败和有部分正文的取消回答均保存调用记录。无正文取消仍按原规则删除空占位，不为追踪改变用户会话语义。实际证据快照仍使用既有受控测试开关。测试消息接口可返回 generation_trace，评测报告将其与本轮证据关联；普通页面不堆放诊断字段。

## 验证与下一步

离线测试覆盖共享 Provider 并发、独立尾部 usage、无 usage、流式空回答重试、同步截断重试、非法用量、任意结束原因清理、流式 done 与数据库记录。使用 HTTP/模型替身，不发送私人数据，不新增收费调用。

最终后端全量：750 passed，116.91 秒。前端 typecheck、OpenAPI 34 条路径和前端生成类型契约、compileall、git diff --check 均通过。本轮没有重跑浏览器 E2E 或真实模型质量评测，不据此声称回答质量提升或发布门禁完成。

下一步是固定 v2 实际证据与本轮调用记录的新评测基线。要分别检查回答质量、时间、已观测用量和未观测轮次，不能把记录更完整当成准确率提升证明。
