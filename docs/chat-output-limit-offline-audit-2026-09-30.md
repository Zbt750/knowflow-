# 问答输出上限与重试：离线元数据盘点

本轮没有调用模型或读取开发库问答内容。新增 `scripts/analyze_chat_generation_reports.py`，只接受明确列出的本地报告文件，输出调用追踪、重试、截断、耗时和可观测 token 汇总；不打印问题、回答、资料片段或提示词。失败回答的追踪可能藏在 `failure_diagnostic.generation_trace`，工具已纳入，不能把这些请求当成没有发送。

对四份隔离报告逐份统计：

| 报告 | 有追踪的请求 | 完成回答 | 失败回答 | 有重试 | 输出上限截断 |
| --- | ---: | ---: | ---: | ---: | ---: |
| v3 基线 | 14 | 14 | 0 | 0 | 0 |
| v3.1 基线 | 15 | 15 | 0 | 1 | 0 |
| v4 首次文件复测 | 3 | 0 | 3 | 3 | 0 |
| v4 重新授权复测 | 3 | 3 | 0 | 1 | 1 |

三个失败回答均发生在此前模型端不可用期间，重试原因是 `generation_failed`，不是输出上限。v3.1 的一次重试也是 `generation_failed`。**完成的 32 条回答里只观察到 1 次输出上限**，就是 v4 跨文件比较；它首轮 4000 completion-token 用尽，第二轮 8000 预算完成。两轮合计观测 12081 token、总耗时 41.6 秒、首次可用正文 39.9 秒。其他两条 v4 文件题约 4 秒完成。

这不是生产流量统计：报告样本小、跨不同提示词版本，且主要是人工设计的合成问题；32 条中只有 1 条 v4 跨文件题。不能据“1/32”认定线上截断率，也不能据“v4 的 1/3”认定所有跨文件问题都慢。当前证据支持保留全局 4000→8000 的一次性重试机制，不支持立刻把所有请求的首轮预算翻倍。要验证定向预算优化，下一步需在事先限定的同类场景上比较首轮完成率、首正文时延、最终答案要点覆盖和两轮实际用量；这会产生新的模型调用，须单独授权。

离线工具与现有 RAG 诊断相关回归 36 项通过，未改变业务问答行为、评分公式或原始报告。
