# 仓库资产与稳定检查点规则

适用：主体功能冻结后的源码检查点。安装包仍暂停，形成提交不代表内容核验或发布验收通过。

## 可进入 Git

- 源码、迁移、依赖声明、构建配置、OpenAPI 与生成类型。
- 公开占位配置；`.env.example` 中的回环数据库口令仅供本地开发，生产必须替换。
- 合成测试集、测试脚本、结构化人工检查记录、脱敏统计和工程文档。
- 自有讲解与待核验内容的状态信息；收录不等于正确性已经核验。

## 仅本地保存

- 实际环境变量、密钥配置文件、数据库、向量索引、上传资料。
- 原卷 PDF、图片、OCR 原始转录、私人上下文快照、完整运行日志和评测报告。
- 模型缓存、虚拟环境、依赖目录、构建产物及数据备份。

这些内容由忽略规则排除；源码提交不会备份它们。原卷和第三方题目进入公开仓库前，必须单独确认许可、来源和分发范围，不因公开可访问就认定可以再分发。

## 提交门禁

1. 运行 `scripts/audit_repository_checkpoint.py`，记录逐文件 SHA-256、HEAD、文件数和候选内容摘要。
2. 人工核对命中；扫描输出不包含密钥值。测试用假值只允许明确列出的字面值且限定测试目录，真实密钥格式仍阻断。
3. 只暂存审计清单中的路径，不执行无差别 `git add .`。
4. 用 `--staged` 再扫描实际完整索引，检查工作区与索引内容摘要一致，再运行 `git diff --cached --check`。
5. 形成本地检查点；上传 GitHub 是另一个明确授权的步骤。

扫描是启发式，不是完整安全审计、版权证明或全部旧历史审计。依赖声明尚不等同于锁定运行环境，源码可恢复也不等同于干净机器上安装可复现。

## 当前 checkpoint 的复现边界（2026-10-03）

- `seed/lessons` 是应用运行所需的发布资源，应与 `scripts/lesson_content_catalog.py`、生成脚本及逐节点状态清单一起跟踪。派生正文可以生成，但不因“generated”就删除其已跟踪发布副本。
- OpenAPI 与生成 TypeScript 类型继续一并跟踪；虚拟环境、构建产物仍排除。Docker 构建上下文另行排除 `.venv-ragas` 和 `.venv-desktop-build`，不混淆 `.gitignore` 与 `.dockerignore`。
- 本地题目处理脚本只保存流程，不包含题干输入。`prepare_local_math_completion.py` 需要显式提供 `--source-pdf` 和 `--intake-dir`，输出限制在被忽略的 `storage/question-intake`。缺少私人输入只影响内容录入，不应阻止正常应用启动。
- 源码提交不能恢复数据库中的52道已录入在线题。使用独立的私有逻辑数据库备份和来源数据备份；源码 checkpoint 与数据恢复点分开记录。
- 本地备份工具 `create_development_checkpoint_backup.py` 使用 `pg_dump`，不复制运行中的 `.pgdata`。Windows新建备份目录只授予当前用户访问；备份不加密，仍属私人资产，不能公开上传。密钥配置、模型、向量索引及外部桌面原卷不包含在此备份内。
- `observed-python-packages.json` 记录备份运行的 Python 环境版本，不是解析完成的依赖锁文件，也不能代表系统Python或所有虚拟环境。后续严格复现仍需要平台特定依赖锁与干净环境验证。
