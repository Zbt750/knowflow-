# 多文件真实问答深度评测（2026-09-27）

## 结论

单文件概述、细节、数学计算、版本数值和基本多轮本次表现较好；
**多文件明确比较仍有稳定的召回范围缺陷**。接口完成、引用编号存在，
不能作为回答完整或忠实的替代证据。

60 次真实 Chrome 前端询问，逐条保存实际模型/系统回答，再对照原文人工复核：

| 复核结果 | 次数 | 含义 |
|---|---:|---|
| 未发现实质内容问题 | 51 | 仅限本次样本，不代表普遍准确率 |
| 多文件任务未完成 | 7 | 丢掉一份、误判歧义，或缺少文件内例题 |
| 核心数值正确但有无依据细节 | 1 | 把“样本数”补成“人数” |
| 错别字标题只返回澄清 | 1 | 未编造，但未识别用户已说明的错字 |

上述分类互斥。多文件失败样本中另有一处常识数学表述缺少适用条件。
**不是新 RAGAS 分数，也不能把 51/60 宣称为系统通用准确率。**

## 已确认的问题

### P1：明确点名两份文件，检索范围仍按单文件处理

问题：

> 对比极限与导数讲义和积分专题讲义，两份的核心内容有什么区别，各举一个文件里的例子。

两份已ready，单独询问均能正确读取。实际回答只引用《极限与导数讲义》，
声称本轮没有《积分专题讲义》片段，并以常识补充代替文件比较。
主测 `cross-math` 检索8片段，引用来源全部为前者。

追加复现：

| 用例ID | 实际结果 |
|---|---|
| probe-cross-repeat | 同问重测，仍缺积分文件 |
| probe-cross-reversed | 颠倒顺序并写两个完整书名，仍缺积分文件 |
| probe-cross-equal | 两个等长完整蓝杉书名同时概述，系统要求再写完整资料名 |
| probe-cross-shorthand | 简称两份讲义，系统要求只能指定那一份 |
| probe-follow-start | 同会话先要求两文件比较，仍只读一份 |
| probe-follow-retry | 明确要求重读两份后只取各一处范围/误区证据，仍无法给出文件内例题 |

源码依据：`backend/chat/service.py` 的 `_matching_materials` 取全局最长命中
（`best = max(...)`，仅保留同最高分资料），导致明确提到的短标题被丢弃。
`_detail_material_scope` / `_overview_hits` 又把多个匹配当成单文件歧义，
没有区分“明确选了两个文件”与“一个名字对应多份文件”。
因此这不是单纯增加chunk数量或回答token就能解决的问题。

建议：按每个明确文件提及分别解析；多文件比较保留所有目标ID，按文件分别召回，
保证每份的章节/例题覆盖。缺证据先做针对该文件的补检索，不能先用常识兜底。
为比较意图与真正名称歧义设置不同分支和回归用例。

### P2：数值正确仍可能补出无依据单位

`table-weighted` 正确算出 84%，但说“甲组20人、乙组30人、丙组50人”。
原文只有样本数，并未说明样本是人。属于忠实性偏差，不是计算错误。

建议：资料回答保留原文对象与单位，不擅自补充人、年、作者或其他属性；
引用卡编号通过不能替代语义忠实性检查。

### P2：常识兜底的条件表达仍不稳定

`probe-follow-retry` 常识段写“驻点只是极值点的必要条件”，没有说明可导、
内点等前提。不能对任意极值点无条件这样说；本套资料中的 `|x|` 在0处
极小但不可导，因而不是驻点，即是反例。

单独追加 `edge-extremum-necessary` 明确询问可导条件时，模型能给出正确解释。
说明它并非完全不会这个知识，但常识补充没有稳定保留条件。
建议约束常识段说明适用前提，避免为了补充内容省略必要条件。

### 效率与体验改进项

主测50条：均值8.56秒，中位数5.63秒，最近秩P95为45.13秒，最长54.61秒。
全部60条：均值8.50秒，中位数5.63秒，最近秩P95为19.68秒，最长54.61秒。
追加短澄清样本改变小样本P95，不能据此宣称性能改善。
60条中13条超过10秒，3条超过30秒：

| 用例 | 耗时 | 正文字符数 |
|---|---:|---:|
| acceptance-detail | 45.4秒 | 1335 |
| math-detailed | 54.6秒 | 2848 |
| manual-detail | 45.1秒 | 1727 |

这些是完整回答耗时（含页面发送、SSE终态、持久化检查），不是首token时延。
未单独记录检索、模型思考、首正文token耗时，不能凭结果断言慢在检索。
建议分段打点后针对慢阶段优化；不应为了提速牺牲全部章节覆盖。

“简短一点”仍输出1542字符，有长度自适应体验空间；明确“不超过150汉字”
得到118汉字，满足要求，因此没有把它误报为硬字数违规。
“积分专题讲议”错别字返回补文件名；建议展示相近标题供确认，不自动读错文件。

## 本次没有发现问题的路径

- 《验收》两种概述均覆盖A–G；150汉字概述仍保留全部阶段。
- 数学八章与手册十章概述覆盖完整；先只问第一章，再问全篇，能覆盖其余章节。
- 洛必达条件/不适用反例、等价替换抵消、隐函数斜率与切线、连续不必可导、
  驻点不必极值、换元/分部/反常积分边界，主要结论均与本套原文一致。
- 蓝杉新旧版合格线、复测间隔、频次、时长、追加上限及控制码未混用；
  多轮切换版本也能更新数值。
- 总正确率84%、每题2秒计算正确；丁组数据、作者出生日期、未提供的token配置未编造。
- 内置模式误问已上传验收文件时立即提示切换，没有读入个人文件，也没卡住。
- 60条无SSE错误、无浏览器pageerror；保存的assistant正文与终态正文逐字一致。
- 正文引用标签均有对应引用卡。但它仅证明结构完整，不证明每句话有语义支持。
- `-\\frac16` 被初版正则误判，人工已确认为正确的 -1/6，没有计为模型错误。
