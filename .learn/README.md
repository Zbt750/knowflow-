# 把自己 AI 写的项目，拆成自己的

> 一句话：**不靠听讲，靠出题。测试判卷，AI 批改。**

这个目录不是笔记，是练习场。产出物是你的代码和你的差异笔记，不是"看过的文档"。

---

## 为什么你这个项目适合这么干

| 条件 | 你的项目 | 意味着什么 |
|---|---|---|
| 代码量 | 后端约 4 万行（services 2.5 万行，最大单文件 1503 行） | 整体拆必死，只能按链路切、按文件挖 |
| 测试 | 316 个测试文件（unit 228 / integration 88 / retrieval 3） | **现成的判卷器**，绿了就是过了 |
| 结构 | retrieval / ingestion / chat / mastery / services 分层清晰 | 边界好切，挖空一个文件不会炸一片 |
| 归属 | 全部是 AI 写的，你会用但不完全懂 | 正是"重建"这套方法的适用场景 |

拆别人的项目，写错了没人告诉你；拆自己的，pytest 会当场告诉你。**这是你唯一比看开源项目强的地方，必须用足。**

---

## 核心机制：讲解员 vs 出题人

两种做法的差别不在效率，在记忆留存。

| | 讲解员模式（大多数人做的） | 出题人模式（本目录） |
|---|---|---|
| AI 干什么 | 逐行讲这个文件写了啥 | 把实现挖空，只给规格和验收测试 |
| 你干什么 | 读、点头、以为懂了 | 合上原文件，徒手写回来 |
| 判分 | 无（"看懂了吗？懂了"） | pytest 红/绿 + 与原实现的 diff |
| 一周后 | 忘了 | 记得，因为手写过 |
| 产出物 | 一份读过的文档 | 一份自己的实现 + 一份差异笔记 |

**听讲产生的"懂了"是错觉。** 你现在能讲清 `chat/service.py` 那 2529 行在干什么吗？如果不能，那过去所有"让 AI 讲讲这个模块"的操作都是无效功。

## 四个阶段

```
P0 测绘 ──→ P1 出题 ──→ P2 徒手重写 ──→ P3 批改 + 口试
  AI 干       AI 干        你干            AI 干
 一次        每个模块      每个文件        每个文件
```

### P0 测绘（只做一次）
AI 产出 `P0_项目地图.md`：模块职责、端到端链路、关键文件清单、测试映射表、分级（哪些必懂/哪些当黑盒）。
**判定标准**：你能指着地图，说出"用户上传一份 PDF，最后在聊天里被检索到"经过哪 6 个文件。

### P1 出题（每个模块一次）
AI 产出任务卡（见 `任务卡/T01_RRF融合.md`）：
- 要重写哪个文件、哪几个函数
- 函数签名 + 语义规格 + 边界条件（不给实现思路）
- 对应哪几个测试，必须全绿
- 允许看什么（测试文件、调用方、类型定义）
- 禁止看什么（原实现）

**判定标准**：任务卡里没有任何一行能让你直接抄。

### P2 徒手重写（你干）
只看任务卡 + 测试 + 类型定义。写。跑 pytest。红→改→绿。
**判定标准**：目标测试全绿，且**没有 import 原模块的实现**（自己写，不是转发）。

### P3 批改 + 口试（AI 干）
AI 做三件事：
1. `git diff` 你的实现 vs 原实现，分三类反馈：功能漏了 / 写法差异 / 为什么原版更好
2. 追问 3 个"为什么不那样写"（例：为什么 RRF 不看原始分数？）
3. 打分：能独立解释 / 能改但不解 / 靠猜通过

**答不上来第 2 条 = 回炉重写，不进入下一个文件。**

## 五条铁律

1. **一次只挖一个文件，≤ 150 行。** 超过就换更小的入口。`fusion.py` 60 行是起点，不是随便选的。
2. **P2 期间不许看原文件、不许向 AI 要代码。** 可以问"这个函数该不该处理空输入"这类规格问题，不能问"帮我写"。
3. **测试绿了才算过。** 不绿不许进下一个。不许改测试来迁就自己的实现。
4. **只用独立分支 + 隔离测试库。** 绝不碰真实库 `127.0.0.1:5433/kaoyan`，绝不改 main 上的产品代码。
5. **批改必须看 diff。** 没有 diff 的"写完了"等于没写。

## 一节课 90 分钟怎么排

| 时段 | 干什么 |
|---|---|
| 0–10 min | 读任务卡，读验收测试，把 7 个测试逐条翻译成中文的"它要我保证什么" |
| 10–55 min | 徒手写。卡住时只允许看调用方和类型定义，不许看原文件 |
| 55–70 min | 跑 pytest，红一条改一条，直到全绿 |
| 70–85 min | AI 批改 + 口试 3 问 |
| 85–90 min | 在任务卡底部写 3 行"我漏了什么"（这份总结才是复利） |

一个 60 行的文件，90 分钟。不要嫌慢——这是唯一能让你真正拥有这 4 万行的速度。

## 目录与命令

```
.learn/
├── README.md                 # 本文件
├── P0_项目地图.md            # 测绘结果
├── 任务卡/T01_RRF融合.md     # 逐张增加
├── 模板/                     # 任务卡模板 + 出题提示词
└── tools/blank.py            # 挖空脚本：把指定函数体换成 NotImplementedError
```

练习流程（**每一步都别跳**）：

```bash
cd D:/考研跑通项目

# 1. 建练习分支（不碰 main）
git checkout -b practice/t01-rrf

# 2. 生成练习题：把 fusion.py 的三个函数体挖空
python .learn/tools/blank.py backend/retrieval/fusion.py \
    --funcs reciprocal_rank_fusion,fuse_ranked_ids,rank_map \
    --out backend/retrieval/fusion.py

# 3. 徒手写（此时 fusion.py 里只剩签名 + docstring + raise NotImplementedError）

# 4. 跑验收测试
python -m pytest tests/retrieval/test_retrieval_core.py -q

# 5. 批改：看你的实现 vs 原实现
git diff main -- backend/retrieval/fusion.py

# 6. 收工：回到干净状态
git checkout main && git branch -D practice/t01-rrf
```

> 第 2 步会**直接改写** `backend/retrieval/fusion.py`。因为已经在独立分支上，`git checkout main -- 该文件` 随时能还原。这是唯一安全的挖空姿势——不要用 `git stash`，不要在主分支上挖。
